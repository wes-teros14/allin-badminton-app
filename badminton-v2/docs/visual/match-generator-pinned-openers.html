Hand-picked opening games — where they would hook into the generator

Feasibility sketch, no code changed. The engine is src/lib/matchGenerator.ts; the admin drives it from src/components/MatchGeneratorPanel.tsx. Amber boxes are the touch points a “fixed game 1 (and 2)” setting would need.

The engine is three phases over one matrix

Phase 1

Assignment — who plays in each game

Builds a string[][]: one row per game, four player ids per row. Each player gets a target game count first, then rows are filled most-games-remaining-first, skipping anyone who just played.

buildAssignment() · findValidGroup() · pickGroup()
Hook 1Seed rows 0…k−1 with the pinned groups before the loop starts, subtract one from each pinned player’s remaining count, and seed prevMatchPlayers from the last pin so game k+1 still avoids back-to-back play.
Phase 3 (runs on the matrix)

Optimisation — shuffle until the score stops improving

Simulated annealing, 50 starts × 2000 trials by default. Two moves only: swap one player between two rows (mutateCrossSwap) or swap two whole rows (mutateRowSwap).

optimizeAssignment() · evaluateSessionScore()
Hook 2Both moves draw their row indices at random from [0, length). Change that to [k, length) and a pinned row can never be touched. The scorer needs no change — it should keep seeing the pinned games so rest, streaks and fairness are optimised around them.
Phase 2 (runs last, per row)

Team formation — which 2 v 2 split

For each row of four, tries the three possible splits and keeps the one with the smallest level difference. This is where the four ids become team1 / team2.

formTeams() · assignmentToMatches()
Hook 3A pinned row must skip this step and keep the split the admin chose, otherwise “A & B vs C & D” could come back as “A & C vs B & D”. Pinned rows carry their ids already in team order and are passed through as-is.

Edge cases the setting has to answer

CaseWhat happens todayProposed handling
Same player in two slots of one pinned gameBlocked on the edit form by validateMatchPlayers; DB has matches_distinct_players_checkReuse the same validator on the pin form; disable already-chosen players in the other three dropdowns, as the edit form does
Same player in pinned game 1 and game 2n/aAllow, but warn — with two courts these start together, so that player would be double-booked. Scorer would also charge a streak penalty, but as a constant it cannot steer anything
Pinned four exceed the level-spread limitEngine never emits such a row; SA refuses swaps that wouldAllow, warn in the preview. It is the admin’s explicit choice; the spread penalty becomes a constant
A pinned player is removed from the roster before lockingRoster overrides sync live into the panelRefuse to generate with a toast naming the player; the pin must be cleared or replaced
Admin presses “Generate Again”Whole schedule is re-rolledPins survive — they live in generator_settings alongside the other sliders, which is already saved per session and restored on reload
How many games can be pinnedn/aUp to sessions.court_count. Those are the games that start at the same whistle; pinning game 3 is a different idea (“first on deck”) and not what was asked
Nothing downstream changes. A pinned game leaves the engine as an ordinary GeneratedMatch, so lockSchedule, the match board, the live board and the DB constraint all treat it like any other row.
