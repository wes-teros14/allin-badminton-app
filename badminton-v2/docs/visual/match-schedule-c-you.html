What it fixes

  • It answers the actual question. A player opens a 20-game list to find their own name. Today they have to read all twenty cards to do it — the names are set in identical weight and colour with nothing to catch the eye.
  • The admin-only filter becomes the whole idea. Right now there is a bare <select> visible only to role === 'admin', with no label and no “showing 5 of 20” feedback. Here it is a first-class control everyone gets.
  • Your games are marked in two ways — a tinted row and an underlined name — so it does not depend on colour alone.
  • Your record for the night comes free: five games, two won, three left. The data is already loaded to draw the list.
  • Nothing is hidden. Unlike A, all twenty rows are still there in order — the others are just quiet.

Trade-offs

  • It needs to know who you are. That is fine for a signed-in player, but this page is also opened from /session by the admin on a laptop, where “you” is meaningless — so it must fall back to a neutral all-games view. Two states to design, not one.
  • The other fifteen rows are deliberately low-contrast context. If people use this page to look up other pairings, that is now the harder job. Option B treats every game equally.
  • Court is only shown on the hero card, not per row, to keep rows to one line.
  • “3 games away” is a count, not a time — honest, but a player probably wants minutes, and minutes would have to be estimated.

Correction I earlier called the ← My Matches link a bug. It is not. /match-schedule/session/:sessionId renders PlayerListViewInner, which auto-redirects a signed-in, registered player to /match-schedule/session/:id/:nameSlug with replace: true (src/views/PlayerView.tsx:216). The link round-trips through the picker and lands on your own schedule. I traced the route table but not the redirect.

Note This is the only option that could replace a screen rather than just redress one: if All Matches highlights your games, the separate per-player ScheduleView at /match-schedule/session/:id/:nameSlug largely duplicates it.
