Roster — three ways to reset session levels to the /players profile levels

Each roster row's level is a per-session override (session_registrations.level), falling back to the profile level from /players when empty. Once an override is set it sticks for that session, which is how Jerome could read 3 here and 4 on /players. All three mocks start with three rows that differ from their profile (John 2 → 3, Jerome 3 → 4, Bogs 4 → 3). Click the buttons; Reset mock starts over.

Option A

One button in the header, tap twice to confirm

Sits beside the collapse caret, always visible, never takes a row. First tap arms it (“Confirm? (3)”), second tap applies — the same two-tap pattern as Lock Schedule. Changed rows flash their new value; nothing tells you what will change before you tap.

Roster (16), Male (12), Female (4) ▲

    Option B

    Footer row under the list with a count and Undo

    A hairline rule, then “3 levels differ from /players” and a Reset button on the right. The count is the confirmation: 0 differences greys the button out. Applying shows a toast with Undo, so a mis-tap costs one more tap instead of a second confirm up front.

    Roster (16), Male (12), Female (4)▲
      Option C

      Per-row hint, then one action for all

      Every row whose level differs shows a small profile 4 badge next to the select, so the mismatch is visible while you are looking at the player. The header button reads “Reset 3” and applies them all. Most informative; the badges cost a little row width on the rows that differ.
