Match Generator — three ways to remember last week's settings

Every session currently starts scoring weights from hardcoded DEFAULTS (MatchGeneratorPanel.tsx:81-105), even though the same admin runs the same 16-player, 2-court structure most weeks and, per the critique, likely only ever touches 2-3 of the 12 weights. All three mocks assume a locked schedule exists from last week with Repeat Partner Penalty nudged 150→220 and Rest Spacing Penalty nudged 30→60. Click the buttons; Reset mock starts over.

Option A

One-tap banner, nothing changes until you tap it

Panel still opens on DEFAULTS. A dismissible banner above Settings offers “Load last session's settings” when a previous locked config exists. Tapping it fills the draft — still fully editable before Generate. Safest change: nobody's workflow is altered unless they opt in, but it costs a tap every single week for an admin who always wants last week's values.

Option B

Silent default: last week's settings are the defaults

The panel initializes from the most recently locked settings automatically — no tap needed, matching how a recurring tool should behave. A quiet pill next to the header names what's loaded and offers Reset to defaults as the escape hatch. Fastest for the common case; the risk is an admin not noticing they're running last week's tuned values when they meant to start fresh.

Option C

Named presets you build up over time

A preset switcher sits at the top of Settings: My usual (saved from the last locked run), Defaults, and any others the admin names and saves. Most flexible — supports a “tournament night” preset alongside the weekly one — but it's new surface area (naming, saving, managing) for a tool used by exactly one person.
