Why the hybrid, not a full move

Neon Auth never lets the database sleepUsers report it polls every ≤ 274 s, so compute runs 24/7: ~182 CU-hours against a 100 cap, and the app is down around day 17.
Accounts stay exactly as they areNo account migration, no changed IDs, nobody has to sign in again.
Supabase keeps only light workAbout 170 sign-in requests a day plus file lookups, mostly served from the CDN.

Gates that decide go or no-go

G0 · Supabase tokens on NeonDoes Neon accept Supabase sign-ins? If not, stop and re-plan.
G1 · Database can sleep24 h idle, plus a hidden tab: does compute still sleep? If not, the budget breaks.
G2 · Every message arrives3 cheers = 3 toasts; trigger rows reach phones fast.
G3 · Query parityThe app’s real queries and RPCs, logged in and logged out.
G4 · New playerA first Google sign-in still creates a profile.
G5 · Cold start + egressFirst request after a sleep; bytes per session.
G6 · Supabase pause ruleCan an auth-only Supabase project be paused?
